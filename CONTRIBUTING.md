# Contributing

Thanks for helping improve DesignShelf.

## Before opening a pull request

1. Search existing issues and pull requests.
2. Open an issue before starting a large feature or architecture change.
3. Keep changes focused and preserve the existing visual language.
4. Test the affected flow in both desktop and narrow viewports.
5. Do not add analytics, accounts, or remote persistence to the MVP.

## Local development

Serve the repository from its root:

```bash
python -m http.server 4173
```

Open `http://localhost:4173` and test with the included demo data.

## Pull requests

- Explain the user problem and the chosen approach.
- Include screenshots for visible changes.
- Describe manual verification.
- Keep refactors separate from feature changes when practical.
- Do not commit personal DesignShelf backups or licensed font files.
